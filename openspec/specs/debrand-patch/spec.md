## Purpose

定义构建前对上游源码工作副本执行的去品牌改写规则：移除面向用户的上游仓库入口，并把在线更新来源切换到本仓库，同时保证漏改一定会让流水线失败而不是静默产出错误版本。

## Requirements

### Requirement: 移除前端上游仓库入口

改写后的前端产物 MUST NOT 向任何用户展示指向上游仓库的可点击 GitHub 入口。涉及三处：站点首页页脚、API Key 用量页页脚、登录后右上角用户下拉导航（该入口原本仅管理员可见）。

移除入口的同时，MUST 一并移除因此失去引用的相关常量与声明；前端构建启用了未使用变量检查，残留声明会直接导致构建失败。

#### Scenario: 访客浏览首页

- **WHEN** 未登录访客打开站点首页
- **THEN** 页脚不再出现 GitHub 链接，其余页脚项（如文档链接）保持原有排布且可正常点击

#### Scenario: 管理员打开右上角下拉

- **WHEN** 管理员登录后展开右上角用户下拉导航
- **THEN** 下拉中不再出现 GitHub 项，其余项（个人资料、API 密钥、联系方式等）位置与行为不变

#### Scenario: 用户查看 API Key 用量页

- **WHEN** 用户打开 API Key 用量页
- **THEN** 页脚不再出现 GitHub 链接

### Requirement: 手动回滚指引指向本仓库产物

版本面板中提供给管理员复制执行的手动回滚命令 MUST NOT 指向上游的产物来源。

- 依赖上游仓库中 `deploy/install.sh` 的脚本回滚方式 SHALL 被移除：本仓库不携带该目录，改指本仓库会失效，保留原样则会把实例换成上游构建。
- 容器回滚指引 SHALL 使用本仓库发布的容器镜像。
- 内置的一键在线回滚与「查看 Release」链接不受影响，它们的数据来自后端，已随更新来源一并指向本仓库。

#### Scenario: 管理员复制容器回滚命令

- **WHEN** 管理员在版本面板选择一个历史版本并复制容器回滚命令
- **THEN** 命令中的镜像为本仓库发布的镜像，按该命令重建的实例仍是去品牌构建

#### Scenario: 管理员查看手动回滚方式

- **WHEN** 管理员展开手动回滚区域
- **THEN** 不再提供依赖上游 `install.sh` 的脚本回滚方式

#### Scenario: 一键在线回滚

- **WHEN** 管理员使用内置的一键回滚
- **THEN** 回滚产物来自本仓库的历史 Release，行为不受本项改动影响

### Requirement: 保留功能性文档跳转

改写 MUST NOT 移除或改写管理后台内指向上游文档的功能性跳转（合规文档、支付接入文档）。这些链接指向上游仓库中的文档路径，本仓库不存在对应路径，改指本仓库将导致 404。

#### Scenario: 管理员打开合规确认弹窗

- **WHEN** 管理员触发合规确认弹窗
- **THEN** 弹窗中的文档链接仍然有效并指向上游文档

#### Scenario: 管理员查看支付配置说明

- **WHEN** 管理员在设置页点击支付接入文档链接
- **THEN** 链接仍然有效并指向上游文档

### Requirement: 在线更新来源指向本仓库

改写后的后端 SHALL 以本仓库作为在线更新的唯一来源：版本检测、可回滚版本列表、产物下载均 MUST 从本仓库的 Release 获取。

改写 MUST NOT 放宽下载来源的域名校验；本仓库同样托管于 GitHub，原有的下载域名限制继续适用。

#### Scenario: 实例检查更新

- **WHEN** 实例执行更新检测
- **THEN** 检测结果基于本仓库的最新 Release，展示的版本号与发布说明来自本仓库

#### Scenario: 实例查看可回滚版本

- **WHEN** 管理员查看可回滚的历史版本列表
- **THEN** 列表来自本仓库已发布的历史 Release

#### Scenario: 下载来源被篡改

- **WHEN** 更新流程拿到的下载地址不属于允许的 GitHub 域名
- **THEN** 更新 MUST 被拒绝并报错

### Requirement: 改写命中断言

每一处改写 SHALL 在执行前断言目标文本存在、在执行后断言目标文本已消除。任一断言失败 MUST 使改写整体失败并阻断构建。

**理由**：上游发版频繁，源码随时可能重构。断言把"上游改了结构导致补丁失效"从静默漏改变成显式失败。

#### Scenario: 上游重构导致某处未命中

- **WHEN** 上游改动使某处目标文本不再匹配
- **THEN** 改写 MUST 失败并明确指出未命中的位置，MUST NOT 继续构建

#### Scenario: 改写全部命中

- **WHEN** 全部目标位置改写成功
- **THEN** 后置断言确认前端入口、手动回滚指引与后端上游更新源均已消除，流水线继续构建

#### Scenario: 上游标识以运行时拼接的形式残留

- **WHEN** 某处上游标识以 `owner/repo` 片段的形式保存、URL 在运行时才拼出，因而完整地址的探针扫不到
- **THEN** 产物校验 MUST 通过游离片段探针发现它并让流水线失败

### Requirement: 改写不落入本仓库

改写 SHALL 只作用于构建期的上游源码工作副本。本仓库 MUST NOT 保存上游源码副本，也 MUST NOT 因发布流程产生上游源码的提交。

#### Scenario: 一次成功发布之后

- **WHEN** 某个版本发布成功
- **THEN** 本仓库的文件内容仅包含流水线与改写脚本本身，不含上游源码
